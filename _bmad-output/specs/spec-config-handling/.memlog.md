- (event) create from doc/preliminary_study.md; slug config-handling given by user; input rich, express distill without elicitation
- (assumption) spec scope is the whole engine described in the study, not only file loading: the configuration model is the engine's behavioral contract, so it cannot be specced apart from reconciliation, time and tooling
- (direction) why: event-driven trigger->action tools (Home Assistant, openHAB, Node-RED) make overlapping rules order-dependent and undebuggable; a custom Go engine with desired-state reconciliation is chosen instead, headless, CLI-operated, in a Proxmox container
- (constraint) MQTT is the only device interface; Zigbee devices are reached through Zigbee2MQTT
- (constraint) configuration is YAML plus an embedded expression language; no GUI; every operation is available from the CLI; runs in a container on Proxmox
- (constraint) implementation language Go, go.mod declares go 1.23 or later (timer.Reset semantics)
- (constraint) desired-state reconciliation, never trigger->action: every input change or time deadline recomputes all outputs from the global state and current time; publish only differences
- (constraint) priority is list order, first match wins, for output policies and latch transitions alike; default applies when nothing matches
- (constraint) edges (button presses) are consumed only by latches; inputs, derived states and policies read levels only
- (constraint) each output is defined exactly once across the whole configuration, including conf.d merges
- (constraint) invalid configuration (unknown reference, type mismatch, uncompilable expression, duplicate output) refuses to start the service
- (constraint) time is read only through an injected clock so every time-dependent behavior runs under a simulated clock
- (constraint) local time uses an explicitly configured time zone (Europe/Paris), never the container's TZ
- (constraint) a press acts immediately; the engine never delays an action to disambiguate multi-press gestures
- (capability) CAP-1 load configuration from a single YAML file or a conf.d directory (one file per room/domain) merged at load time, validated before start
- (capability) CAP-2 inputs map an MQTT topic + message field to a typed variable holding the last known value
- (capability) CAP-3 derived states are named reusable expressions over inputs, latches and current time
- (capability) CAP-4 latches turn edge events into lasting values: declared values, initial, ordered transitions (on event, from values, optional when using state_age), actions such as toggle, reset_after timeout
- (capability) CAP-5 outputs declare command topic, default, ordered policies (name, when, state) and min_on/min_off anti-short-cycling
- (capability) CAP-6 reconcile loop recomputes every output on each input change or deadline, publishes only diffs, compares against observed state when an output is linked to an input via observed, so lost messages or manual relay presses self-correct
- (capability) CAP-7 time-based functions report the instant their value may change; engine wakes at the nearest deadline; functions: any, all, duration, since_true, since_true_any, time_between (crosses midnight), sun_below_horizon(offset) from configured coordinates
- (capability) CAP-8 explain command shows per-output policy evaluation and the deciding policy; same trace logged on every output state change
- (capability) CAP-9 test command runs scenarios (given, events, expect, then) under a simulated clock
- (capability) CAP-10 dry-run mode computes and logs decisions without publishing
- (decision) stack: expression language expr-lang/expr or cel-go (compile at load, custom functions, deadline reporting); sunrise via nathan-osman/go-sunrise; no dependency graph, full recompute on every event keeps explain consistent; Starlark rejected for now
- (decision) time handling: computed deadlines chosen over periodic tick
- (note) double press is not a gesture: second press within 1s upgrades latch level via state_age; Zigbee buttons with native multi-click send double instead of two singles -> disable it in Z2M or map double to the transition
- (note) known behaviors: lamp 3 stays on after switch B off at night until 3 min after last motion (fix: auto/on/off latch with forced-off policy on top); on restart since_true_any is infinite so boiler stays off until first motion and latches reset; motion thresholds count from occupancy back to false (Z2M sensor delay 60-90 s)
